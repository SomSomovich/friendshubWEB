0. ОБЩЕЕ

Аутентификация
--------------------------------------------------------------------------------
Пользовательский API:
    Authorization: Bearer <session_token>
    X-Device-Number: <n>          опционально; если задан, должен совпадать
                                  с device_number сессии, иначе 403

Bot API:
    X-Bot-Token: <bot_token>      без префикса Bearer


Формат ошибок
--------------------------------------------------------------------------------
Все ошибки — JSON:

    {
      "error": "not_found",
      "message": "not found"
    }

С details (например, replenish_required):
    {
      "error": "replenish_required",
      "message": "prekey pool needs replenishing",
      "details": {
        "one_time_available": 2,
        "kyber_one_time_available": 5,
        "minimum_required": 4
      }
    }

Значения error → HTTP статус:
    not_found            404
    unauthorized         401
    forbidden            403
    bad_request          400
    conflict             409
    rate_limited         429 (с Retry-After)
    replenish_required   503
    payload_too_large    413
    internal_error       500


Rate limits
--------------------------------------------------------------------------------
Все лимиты — фиксированное окно, 60 секунд.

    /register                          5  / IP
    /login, /login/2fa                10  / IP
    /2fa/*                            10  / IP
    /account/delete/*                 10  / IP
    /attachments/init                 30  / account
    /accounts/{id}/devices            30  / account
    /accounts/{id}/devices/{n}/bundle 10  / (account, device)
    /handles/*                        60  / account
    /groups/by-handle/{h}             60  / account
    /search, /contacts/search         30  / account
    /contacts/* (прочие)              30  / account
    typing (WS)                       20  / (account, conversation)
    Bot: /getUpdates                  60  / bot
    Bot: /accounts/{fh}               60  / bot

При превышении:
    HTTP/1.1 429 Too Many Requests
    Retry-After: 42
    { "error": "rate_limited", "message": "rate limited" }


Соглашения
--------------------------------------------------------------------------------
- timestamps       — unix-секунды (i64), если не сказано иное
- id               — UUID-строки (в WS — 16 байт)
- пагинация        — курсорная, параметры before / limit
- формат            — snake_case
- "…" в примерах   — сокращение, не литерал

1. AUTH
================================================================================

--------------------------------------------------------------------------------
POST /api/v1/register
--------------------------------------------------------------------------------
Auth: нет
Лимит: 5/IP/мин

Запрос:
    { "password": "correct horse battery staple" }

Ограничения пароля: 8..128 символов.

Ответ 201:
    {
      "id": "<uuid>",
      "user_id": 42,
      "fh_number": "FH1234567",
      "username": "User_1234567"
    }

Ошибки:
    400 — пароль не проходит проверку длины
    429 — rate limit


--------------------------------------------------------------------------------
POST /api/v1/login
--------------------------------------------------------------------------------
Фаза 1: пароль. С 2FA вернёт challenge вместо сессии.

Auth: нет
Лимит: 10/IP/мин

Запрос:
    {
      "fh_number": "FH1234567",
      "password": "...",
      "device_number": 1
    }

device_number должен существовать на аккаунте. Исключение — аккаунт без
устройств (bootstrap первого девайса).

Ответ 200 без 2FA:
    {
      "kind": "session",
      "session_token": "<token>",
      "expires_at": 1772592000
    }

Ответ 200 с 2FA:
    {
      "kind": "totp_required",
      "challenge_token": "<token>",
      "expires_in_seconds": 300
    }

Ошибки:
    401 — нет FH, неверный пароль, несуществующее устройство
    429 — per-account lockout или IP rate limit


--------------------------------------------------------------------------------
POST /api/v1/login/2fa
--------------------------------------------------------------------------------
Фаза 2: TOTP или backup-код. Расходует challenge.

Auth: нет
Лимит: 10/IP/мин

Запрос:
    {
      "challenge_token": "<из /login>",
      "code": "123456",
      "device_number": 1
    }

Формат code:
    6 цифр                — TOTP
    A-Z, 2-9 (10 символов) — backup-код (регистр и дефисы не важны)

Ответ 200:
    {
      "kind": "session",
      "session_token": "<token>",
      "expires_at": 1772592000
    }

Ошибки:
    401 — нет/протух challenge, неверный код, несуществующее устройство
    429 — lockout или IP rate limit


--------------------------------------------------------------------------------
POST /api/v1/logout
--------------------------------------------------------------------------------
Отзывает текущую сессию.
Auth: Bearer
Ответ: 204


--------------------------------------------------------------------------------
GET /api/v1/me
--------------------------------------------------------------------------------
Auth: Bearer

Ответ 200:
    {
      "id": "<uuid>",
      "user_id": 42,
      "fh_number": "FH1234567",
      "username": "User_1234567",
      "avatar_url": "/avatars/<uuid>",
      "totp_enabled": true,
      "custom_status_text": "работаю",
      "custom_status_emoji": "💻",
      "custom_status_expires_at": 1772600000
    }


--------------------------------------------------------------------------------
2FA: enroll / verify / disable
--------------------------------------------------------------------------------
POST /api/v1/2fa/enroll
    Auth: Bearer
    Лимит: 10/IP/мин
    Запрос: {}
    Ответ 200:
        {
          "secret_base32": "JBSWY3DPEHPK3PXP",
          "otpauth_uri": "otpauth://totp/FH:FH1234567?secret=...&issuer=FH"
        }
    Ошибки: 409 — 2FA уже включена

POST /api/v1/2fa/enroll/verify
    Auth: Bearer
    Лимит: 10/IP/мин
    Запрос:
        { "code": "123456" }
    Ответ 200:
        { "backup_codes": ["ABCD2345EF", "GHJK6789MN", ...] }
    Важно: backup_codes показываются ОДИН РАЗ.
    Ошибки:
        400 — нет pending enrollment
        401 — неверный код
        409 — 2FA уже включена

POST /api/v1/2fa/disable
    Auth: Bearer
    Лимит: 10/IP/мин
    Запрос:
        { "password": "...", "code": "123456" }
    Ответ: 204
    Ошибки:
        401 — неверный пароль или код
        409 — 2FA не включена
        429 — lockout


================================================================================
2. ACCOUNT (удаление)
================================================================================

Двухфазное удаление:
  initiate — создаётся pending-запись (не удаляет).
  confirm  — через 5 минут и в течение 5 минут после этого: полная
             повторная аутентификация (пароль + TOTP если включён) и
             hard-delete.
  cancel   — отменяет на любом этапе до confirm.

--------------------------------------------------------------------------------
POST /api/v1/account/delete/initiate
--------------------------------------------------------------------------------
Auth: Bearer
Лимит: 10/IP/мин
Запрос: {}

Ответ 200:
    {
      "confirm_after": 1770000300,
      "confirm_until": 1770000600,
      "confirm_after_seconds": 300,
      "confirm_window_seconds": 300
    }


--------------------------------------------------------------------------------
POST /api/v1/account/delete/confirm
--------------------------------------------------------------------------------
Auth: Bearer
Лимит: 10/IP/мин

Запрос:
    {
      "password": "...",
      "code": "123456"     // обязателен, если 2FA включена
    }

Ответ: 204 (аккаунт удалён)

Ошибки:
    400 — нет pending-записи, отменена, рано или окно истекло
    401 — неверный пароль/код
    409 — окно ещё не открылось / уже закрылось
    429 — lockout


--------------------------------------------------------------------------------
POST /api/v1/account/delete/cancel
--------------------------------------------------------------------------------
Auth: Bearer
Ответ: 204
Ошибки: 404 — нет pending-записи


--------------------------------------------------------------------------------
GET /api/v1/account/delete/status
--------------------------------------------------------------------------------
Auth: Bearer

Ответ 200 (есть pending):
    {
      "pending": true,
      "account_id": "<uuid>",
      "initiated_at": 1770000000,
      "confirm_after": 1770000300,
      "confirm_until": 1770000600
    }

Ответ 200 (нет):
    {
      "pending": false,
      "account_id": null,
      "initiated_at": null,
      "confirm_after": null,
      "confirm_until": null
    }

4. PROFILE
================================================================================

--------------------------------------------------------------------------------
PUT /api/v1/profile/username
--------------------------------------------------------------------------------
Auth: Bearer

Запрос:
    { "username": "John Doe" }

Правила:
    1..64 символа, только [A-Za-z0-9_. ] и одиночные пробелы.
    Запрещено `FH` + только цифры (резервация FH-пространства).

Ответ: 204
Ошибки: 400 — недопустимые символы, слишком длинный, FH-подобный


--------------------------------------------------------------------------------
PUT /api/v1/profile/status
--------------------------------------------------------------------------------
Auth: Bearer

Запрос:
    {
      "text": "работаю",
      "emoji": "💻",
      "ttl_seconds": 3600
    }

Ограничения:
    text         до 100 символов, опционально
    emoji        до 8 символов, опционально
    ttl_seconds  > 0, опционально. Без него — бессрочно.

Ответ: 204
Побочный эффект: presence broadcast всем, кто тебя видит.


--------------------------------------------------------------------------------
DELETE /api/v1/profile/status
--------------------------------------------------------------------------------
Сбрасывает кастомный статус.
Ответ: 204

--------------------------------------------------------------------------------

Лимит: 10/(account,device)/мин

      "kyber_one_time_prekey": { "id": 200, "pub": "<hex>" } | null

Если OTK-пул у цели <= 3:
    HTTP 503
    {
      "error": "replenish_required",
      "message": "prekey pool needs replenishing",
      "details": {
        "one_time_available": 2,
        "kyber_one_time_available": 5,
        "minimum_required": 4
      }
    }

Ошибки: 404 — нет такого устройства

10. SAVED MESSAGES
================================================================================

Одна личная конверсация на аккаунт, видная всем его устройствам.
Envelope'ы saved НЕ удаляются TTL-чисткой (в отличие от остальных).

--------------------------------------------------------------------------------
GET /api/v1/saved
--------------------------------------------------------------------------------
Идемпотентно: создаёт при первом вызове.

Auth: Bearer

Ответ 200:
    {
      "conversation_id": "<uuid>",
      "kind": "saved",
      "created_at": 1770000000
    }


--------------------------------------------------------------------------------
GET /api/v1/saved/messages
--------------------------------------------------------------------------------
История для ТЕКУЩЕГО устройства (device_number сессии).

Auth: Bearer

Query:
    before  (i64, опционально)  Курсор server_timestamp
    limit   (i64, опционально)  1..500, дефолт 100

Ответ 200:
    {
      "envelopes": [
        {
          "envelope_id":             "<uuid>",
          "sender_account_id":       "<uuid>",
          "sender_device_number":    2,
          "recipient_device_number": 3,
          "envelope_type":           1,
          "is_prekey_message":       false,
          "ciphertext":              "<hex>",
          "client_timestamp":        1770000000,
          "server_timestamp":        1770000005
        }
      ]
    }

Порядок: server_timestamp DESC.
Пагинация: before = server_timestamp последнего элемента.

Ошибки: 404 — saved ещё не создан (не вызывали GET /saved)


--------------------------------------------------------------------------------
Отправка в saved
--------------------------------------------------------------------------------
Отправляется по WS обычным EnvelopeUpload. Отличия:
    recipient_account_id = свой
    recipient_device_number = номер целевого своего девайса
    conversation_id = id из GET /saved

Нужно N конвертов — по одному на каждое своё устройство, кроме текущего.

Ограничения:
    - invites для saved → 400 (нельзя ни создать, ни присоединиться)
    - в списке конверсаций появится item с kind = "saved"

11. PINS
================================================================================

Пины — состояние конверсации. Идентификатор — message_id (логический id
клиента, общий на все устройства), не envelope_id.

Для КАНАЛОВ используется /channel-posts/{id}/pin — там другое.

--------------------------------------------------------------------------------
POST /api/v1/conversations/{id}/pinned
--------------------------------------------------------------------------------
Body:
    { "message_id": "<uuid или строка 1..128>" }

Права: любой участник. Идемпотентно.

Ответы:
    201 Created   — только что добавили
    204 No Content — уже был в пинах
    400 — kind=channel (используйте channel-posts/{id}/pin), пустой/слишком длинный message_id
    404 — нет конверсации или не участник
    409 — достигнут кап (PINNED_MAX_PER_CONVERSATION, дефолт 100)

Пример:
    curl -X POST "http://host/api/v1/conversations/$CID/pinned" \
         -H "Authorization: Bearer $T" \
         -H 'Content-Type: application/json' \
         -d '{"message_id":"a1b2c3..."}'


--------------------------------------------------------------------------------
DELETE /api/v1/conversations/{id}/pinned/{message_id}
--------------------------------------------------------------------------------
Права: любой участник.
Ответы:
    204 — удалено
    404 — нет такого пина, или нет конверсации, или не участник


--------------------------------------------------------------------------------
GET /api/v1/conversations/{id}/pinned
--------------------------------------------------------------------------------
Ответ 200:

      {
        "message_id": "<string>",
        "pinned_by_account_id": "<uuid>",

      }
    ]

Сортировка: pinned_at DESC.

Ошибки: 404


Кап: PINNED_MAX_PER_CONVERSATION (env, дефолт 100).

12. READ RECEIPTS
================================================================================

Per-account, не per-device. Прочитал на телефоне — на ноуте бейдж тоже
гаснет. Хранится максимальный server_timestamp.

--------------------------------------------------------------------------------
POST /api/v1/conversations/{id}/read
--------------------------------------------------------------------------------
Auth: Bearer

Body:
    { "up_to": 1770000000 }     // опционально; без него сервер подставит now

Права: любой участник.

Ответ: 204

Ошибки:
    400 — up_to <= 0
    404 — нет конверсации или не участник

Побочный эффект: рассылка WS ServerFrame::ReadReceipt всем участникам
(кроме сделавшего POST, но включая остальные устройства того же account).


--------------------------------------------------------------------------------
GET /api/v1/conversations/{id}/reads
--------------------------------------------------------------------------------
Ответ 200:
    [
      {
        "account_id":   "<uuid>",
        "last_read_at": 1770000000
      }
    ]

Ошибки: 404


Как читать галочки:
    - У каждого твоего отправленного сообщения есть server_timestamp
      (приходит в Receipt после EnvelopeUpload).
    - Для каждого участника B: если B.last_read_at >= server_timestamp
      твоего сообщения — прочитано B.
    - Если это единственное сообщение и B прочитал — вторая галочка.
    - Live через WS ServerFrame::ReadReceipt (см. раздел 27).

23. SEARCH
================================================================================

--------------------------------------------------------------------------------
GET /api/v1/search
--------------------------------------------------------------------------------
Глобальный поиск.

Auth: Bearer
Лимит: 30/account/мин

Query:
    q       (string, обязательно)  3..64 символа
    scope   (string, опционально)  "identifiers" (дефолт) | "all"
    limit   (i64, опционально)     1..50, дефолт 20

scope=identifiers:
    FH-номер аккаунта + handle групп/каналов/ботов.
    Fuzzy через pg_trgm.

scope=all:
    username, FH-номер, title групп/каналов, handle_display, handle.

Ответ 200:
    {
      "results": [
        {
          "entity_type":  "account" | "group" | "channel" | "bot",
          "entity_id":    "<uuid>",
          "display_name": "User_1234567",
          "identifier":   "FH1234567",
          "avatar_url":   "/avatars/<uuid>"
        }
      ]
    }

Поля по типу:
    account  →  display_name = username, identifier = fh_number,
                avatar_url = /avatars/{account_id}
    group    →  display_name = title, identifier = handle (может быть null),
                avatar_url = /conversations/{id}/avatar (может быть null)
    channel  →  то же
    bot      →  display_name = handle_display, identifier = handle_normalized,
                avatar_url = null

Пагинации нет. limit — жёсткий потолок.
Блокировки игнорируются.

Ошибки:
    400 — q пуст / короткий / длинный, невалидный scope
    429 — rate limit

Примеры:
    GET /api/v1/search?q=FH12345
    GET /api/v1/search?q=work&scope=all&limit=10

27. WEBSOCKET
================================================================================
URL: ws://host:8080/ws

Лимиты:
    max message size:  256 KiB
    max frame size:    256 KiB
    max write buffer:  256 KiB
    hello timeout:     10 секунд
    флуд:              100 фреймов/сек x 5 сек подряд = disconnect

Формат: бинарные protobuf-фреймы. Первый фрейм — ClientHello.


Хендшейк
--------------------------------------------------------------------------------
1. Client → Server:
    ClientFrame {
      kind: Hello {
        session_token:     "<из /login>",
        device_number:     <n>,           // должен совпадать с сессией
        client_name:       "friendshub-web",
        client_version:    "1.0",
        protocol_major:    0, protocol_minor: 1, protocol_patch: 0
      }
    }

2. Server → Client:
    ServerFrame {
      kind: Hello {
        session_id: "<uuid>",
        account_id: <16 bytes>,
        device_number: <n>,
        server_timestamp: <unix>,
        protocol_major: 0, protocol_minor: 1, protocol_patch: 0
      }
    }

3. Сервер может сразу прислать backlog:
    ServerFrame {
      kind: Delivery {
        envelopes: [ Envelope, ... ]
      }
    }

Дальше — обычный поток фреймов.


ClientFrame kind's
--------------------------------------------------------------------------------
    ClientHello   hello     (только один раз, в начале)
    Ping          ping      { client_timestamp }
    EnvelopeUpload upload   { envelopes: [Envelope] }    до 128 конвертов
    EnvelopeAck   ack       { envelope_ids: [16 bytes] }
    TypingFrame   typing    { conversation_id: <16 bytes> }   НОВОЕ


ServerFrame kind's
--------------------------------------------------------------------------------
    ServerHello      hello        (после handshake)
    EnvelopeDelivery delivery     { envelopes: [Envelope] }
    EnvelopeAck      receipt      { envelope_ids, server_timestamps }
    Pong             pong         { client_timestamp, server_timestamp }
    ErrorFrame       error        { code, message, fatal }
    PresenceUpdate   presence     { account_id, is_online, last_seen, custom_status_* }
    BotMessageDelivery bot_message { message_id, bot_id, account_id, text, reply_to_message_id, created_at }
    ChannelPostDelivery channel_post { post_id, channel_id, author_type, author_id, text, attachment_ids, reply_to_post_id, created_at }
    TypingDelivery   typing       { conversation_id, account_id }   НОВОЕ
    ReadReceiptDelivery read_receipt { conversation_id, account_id, last_read_at }   НОВОЕ


Отправка сообщений (EnvelopeUpload)
--------------------------------------------------------------------------------
ClientFrame {
  kind: Upload {
    envelopes: [
      {
        envelope_id:              <16 bytes>,
        sender_account_id:        <16 bytes>,
        sender_device_number:     <n>,
        recipient_account_id:     <16 bytes>,
        recipient_device_number:  <n>,
        envelope_type:            <1..15>,
        is_prekey_message:        true | false,
        ciphertext:               <bytes, <= 64 KiB>,
        client_timestamp:         <unix>,
        conversation_id:          <16 bytes>    // пусто = "не в чате"
      }
    ]
  }
}

Ограничения сервера:
    до 128 конвертов в одном Upload
    ciphertext <= 64 KiB
    envelope_type в 1..=15
    sender_account_id должен совпадать с твоим
    recipient_device должен существовать и не быть revoked
    recipients с блокировкой в любую сторону — дропаются молча
    conversation_id проверяется: ты должен быть участником, иначе поле
        обнуляется (envelope сохранится, но не попадёт ни в чей список
        активности)

EnvelopeType (proto):
    1  MESSAGE
    2  SYNC
    3  SENDER_KEY
    4  EDIT
    5  DELETE
    6  REACTION
    7  READ_RECEIPT    (envelope, не WS-фрейм)
    8  TYPING          (через envelope ОТВЕРГАЕТСЯ)
    9  ATTACHMENT_KEY
    10 CALL_OFFER
    11 CALL_ANSWER
    12 CALL_ICE
    13 CALL_HANGUP
    14 CALL_REJECT
    15 BOT_MESSAGE
    (16, 17 — PIN/UNPIN — УДАЛЕНЫ из enum)


Подтверждение (Receipt)
--------------------------------------------------------------------------------
Сервер отвечает на upload:
    ServerFrame {
      kind: Receipt {
        envelope_ids:      [<16 bytes>, ...],
        server_timestamps: [<i64>, ...],     // НОВОЕ, параллельно ids
      }
    }

Контракт:
    - server_timestamps одной длины и порядка с envelope_ids.
    - Заполняет только сервер. В client Ack — игнорируется.
    - Все envelope одного upload-батча имеют ОДИН И ТОТ ЖЕ
      server_timestamp. Это критично для read receipts.
    - Receipt приходит и для повторно отправленных envelope
      (после reconnect, например). Live-доставка не повторяется.
    - Клиент сохраняет для каждого своего отправленного сообщения:
      message_id → server_timestamp.


Typing (новый фрейм)
--------------------------------------------------------------------------------
Клиент → сервер:
    ClientFrame {
      kind: Typing {
        conversation_id: <16 bytes>
      }
    }

Сервер → получателям (кроме отправителя):
    ServerFrame {
      kind: Typing {
        conversation_id: <16 bytes>,
        account_id:      <16 bytes>      // кто печатает
      }
    }

Клиентское поведение:
    - Слать не чаще раза в 3 секунды, пока идёт ввод.
    - Никакого "stop" — прекратил слать, индикатор истечёт.
    - На приёме: держать 5 секунд с последнего фрейма от account_id.
    - Дедуп по account_id.

Серверное поведение:
    - Проверка участия.
    - Для channel/saved — не рассылает.
    - Для group с member_count > TYPING_MAX_GROUP_MEMBERS — не рассылает.
    - Rate limit 20/мин на (account, conversation).
    - Не сохраняется.

Отправка ENVELOPE_TYPE_TYPING через EnvelopeUpload отвергается.


Read Receipt (новый фрейм)
--------------------------------------------------------------------------------
Сервер → всем участникам конверсации (кроме того, кто сделал POST /read),
включая свои другие устройства:
    ServerFrame {
      kind: ReadReceipt {
        conversation_id: <16 bytes>,
        account_id:      <16 bytes>,      // кто прочитал
        last_read_at:    <i64>,           // до какого server_timestamp
      }
    }

Приходит ТОЛЬКО когда read marker реально сдвинулся.
Повторный POST с тем же up_to — ничего не рассылает.

Использование:
    - Обновить локальный read state.
    - Перерисовать галочки: T_read >= server_timestamp сообщения.


Доставка (Delivery)
--------------------------------------------------------------------------------
ServerFrame {
  kind: Delivery {
    envelopes: [ Envelope, ... ]
  }
}

Приходит:
    - live, если получатель онлайн
    - в backlog при WS-подключении (если был офлайн)
    - после reconnect, если не получил ack

Клиент должен отправить ack:
    ClientFrame {
      kind: Ack {
        envelope_ids: [<16 bytes>, ...]
      }
    }


Ping/Pong
--------------------------------------------------------------------------------
ClientFrame { kind: Ping { client_timestamp } }
ServerFrame { kind: Pong { client_timestamp, server_timestamp } }

Флуд-контроль: 100 фреймов/сек, 5 сек подряд выше — disconnect.


Ошибки WS
--------------------------------------------------------------------------------
ServerFrame::Error {
  code:    "protocol" | "unauthorized" | "device_mismatch" | "flood" | …
  message: "…",
  fatal:   true | false
}

fatal=true — сервер закрывает соединение.
Коды fatal:
    handshake        — нет Hello за 10 сек
    timeout          — то же
    protocol         — несовпадение major
    unauthorized     — нет/протух токен
    device_mismatch  — Hello.device_number != session.device_number
    session_revoked  — сессия отозвана
    device_revoked   — девайс отозван
    replaced         — этот девайс подключился заново
    flood            — флуд
    account_deleted  — аккаунт удалён


Переподключение
--------------------------------------------------------------------------------
1. Backoff: 1s, 2s, 4s, 8s, …, max 30s.
2. При подключении — Hello с тем же session_token.
3. Если fatal (кроме flood) — не переподключаться, идти в /login.
