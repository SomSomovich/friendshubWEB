0. ОБЩЕЕ
================================================================================

Базовые URL
--------------------------------------------------------------------------------
Пользовательский API:  http://host:8080/api/v1
Bot API:               http://host:8080/api/bot/v1
WebSocket:             ws://host:8080/ws
Health:                http://host:8080/health


Аутентификация
--------------------------------------------------------------------------------
Пользовательский API:
    Authorization: Bearer <session_token>
    X-Device-Number: <n>          (опционально, но если задан — должен
                                   совпадать с device_number сессии,
                                   иначе 403)

Bot API:
    X-Bot-Token: <bot_token>      (без префикса "Bearer")


Формат ошибок
--------------------------------------------------------------------------------
Все ошибки — JSON. Тело одинаковое для любого эндпоинта:

    {
      "error": "not_found",
      "message": "not found"
    }

Если есть детали:
    {
      "error": "replenish_required",
      "message": "prekey pool needs replenishing",
      "details": {
        "one_time_available": 2,
        "kyber_one_time_available": 5,
        "minimum_required": 4
      }
    }

Значения поля "error":
    not_found            404
    unauthorized         401
    forbidden            403
    bad_request          400
    conflict             409
    rate_limited         429  (заголовок Retry-After)
    replenish_required   503
    payload_too_large    413
    internal_error       500


Rate limits
--------------------------------------------------------------------------------
Все лимиты — на минуту, фиксированное окно, ключ — IP либо account_id,
в зависимости от эндпоинта.

    /register                     5 / IP
    /login, /login/2fa           10 / IP
    /2fa/*                       10 / IP
    /account/delete/*            10 / IP
    /attachments/init            30 / account
    /accounts/{id}/devices       30 / account
    /accounts/{id}/devices/{n}/bundle   10 / (account, device)
    /handles/*                   60 / account
    /groups/by-handle/{h}        60 / account
    /getUpdates (bot)            60 / bot
    /accounts/{fh} (bot)         60 / bot

При превышении:
    HTTP/1.1 429 Too Many Requests
    Retry-After: 42
    { "error": "rate_limited", "message": "rate limited" }


Соглашения
--------------------------------------------------------------------------------
- Все timestamps — unix-время в секундах (i64).
- Все id аккаунтов/конверсаций/устройств — UUID-строки.
- В WebSocket-протоколе UUID передаются бинарно (16 байт).
- Пагинация — курсорная, а не offset. Курсоры описаны в каждом эндпоинте.
- Формат полей — snake_case.
- "…" в примерах — сокращение, не литерал.


================================================================================
1. AUTH
================================================================================

--------------------------------------------------------------------------------
POST /api/v1/register
--------------------------------------------------------------------------------
Создаёт аккаунт. Пароль хешируется на сервере.

Auth: нет
Лимит: 5/IP/мин

Запрос:
    {
      "password": "correct horse battery staple"
    }

Ограничения пароля:
    8..128 символов

Ответ 201:
    {
      "id": "<uuid>",
      "user_id": 42,
      "fh_number": "FH1234567",
      "username": "User_1234567"
    }

Ошибки:
    400 — пароль не проходит проверку длины
    429 — rate limit

Пример:
    curl -X POST http://host:8080/api/v1/register \
         -H 'Content-Type: application/json' \
         -d '{"password":"correct horse battery staple"}'


--------------------------------------------------------------------------------
POST /api/v1/login
--------------------------------------------------------------------------------
Фаза 1 логина: пароль. Если у аккаунта включена 2FA — вернёт challenge
вместо сессии.

Auth: нет
Лимит: 10/IP/мин

Запрос:
    {
      "fh_number": "FH1234567",
      "password": "correct horse battery staple",
      "device_number": 1
    }

device_number — устройство, к которому будет привязана сессия. Оно должно
существовать (или быть "1" для аккаунта без устройств — это bootstrap-случай,
когда регистрируется первый девайс после логина).

Ответ 200 — без 2FA:
    {
      "kind": "session",
      "session_token": "<token>",
      "expires_at": 1772592000
    }

Ответ 200 — с 2FA:
    {
      "kind": "totp_required",
      "challenge_token": "<token>",
      "expires_in_seconds": 300
    }

Ошибки:
    401 — нет такого FH, неверный пароль, либо несуществующее устройство
    429 — аккаунт залочен (per-account lockout) или IP rate limit

Пример:
    curl -X POST http://host:8080/api/v1/login \
         -H 'Content-Type: application/json' \
         -d '{"fh_number":"FH1234567","password":"...","device_number":1}'


--------------------------------------------------------------------------------
POST /api/v1/login/2fa
--------------------------------------------------------------------------------
Фаза 2 логина: TOTP-код или backup-код. Расходует challenge.

Auth: нет
Лимит: 10/IP/мин

Запрос:
    {
      "challenge_token": "<token из /login>",
      "code": "123456",
      "device_number": 1
    }

Формат code:
    6 цифр             — TOTP
    A-Z, 2-9 (10 симв.) — backup-код (регистр не важен, дефисы допустимы)

Ответ 200:
    {
      "kind": "session",
      "session_token": "<token>",
      "expires_at": 1772592000
    }

Ошибки:
    401 — нет/протух challenge, неверный код, несуществующее устройство
    429 — аккаунт залочен или IP rate limit

Пример:
    curl -X POST http://host:8080/api/v1/login/2fa \
         -H 'Content-Type: application/json' \
         -d '{"challenge_token":"...","code":"123456","device_number":1}'


--------------------------------------------------------------------------------
POST /api/v1/logout
--------------------------------------------------------------------------------
Отзывает текущую сессию.

Auth: Bearer
Ответ: 204


--------------------------------------------------------------------------------
GET /api/v1/me
--------------------------------------------------------------------------------
Информация о текущем аккаунте.

Auth: Bearer

Ответ 200:
    {
      "id": "<uuid>",
      "user_id": 42,
      "fh_number": "FH1234567",
      "username": "User_1234567",
      "avatar_url": "/avatars/<uuid>",
      "totp_enabled": true,
      "custom_status_text": "работаю",
      "custom_status_emoji": "💻",
      "custom_status_expires_at": 1772600000
    }


--------------------------------------------------------------------------------
2FA: ENROLL / VERIFY / DISABLE
--------------------------------------------------------------------------------

POST /api/v1/2fa/enroll
    Auth: Bearer
    Лимит: 10/IP/мин
    Запрос: {}
    Ответ 200:
        {
          "secret_base32": "JBSWY3DPEHPK3PXP",
          "otpauth_uri": "otpauth://totp/FH:FH1234567?secret=...&issuer=FH"
        }
    Ошибки:
        409 — 2FA уже включена

POST /api/v1/2fa/enroll/verify
    Auth: Bearer
    Лимит: 10/IP/мин
    Запрос:
        { "code": "123456" }
    Ответ 200:
        {
          "backup_codes": ["ABCD2345EF","GHJK6789MN", "..."]
        }
    Важно: backup_codes показываются ОДИН РАЗ.
    Ошибки:
        400 — нет pending enrollment
        401 — неверный код
        409 — 2FA уже включена

POST /api/v1/2fa/disable
    Auth: Bearer
    Лимит: 10/IP/мин
    Запрос:
        { "password": "...", "code": "123456" }
    Ответ: 204
    Ошибки:
        401 — неверный пароль или код
        409 — 2FA не включена
        429 — аккаунт залочен


================================================================================
2. ACCOUNT (УДАЛЕНИЕ)
================================================================================

Двухфазное удаление:
  Фаза 1 — initiate:  создаётся pending-запись.
  Фаза 2 — confirm:   через 5 минут и в течение 5 минут после этого —
                      повторная аутентификация (пароль + 2FA) и hard-delete.
  cancel: отменяет на любом этапе до confirm.

--------------------------------------------------------------------------------
POST /api/v1/account/delete/initiate
--------------------------------------------------------------------------------
Auth: Bearer
Лимит: 10/IP/мин

Запрос: {}

Ответ 200:
    {
      "confirm_after": 1770000300,
      "confirm_until": 1770000600,
      "confirm_after_seconds": 300,
      "confirm_window_seconds": 300
    }


--------------------------------------------------------------------------------
POST /api/v1/account/delete/confirm
--------------------------------------------------------------------------------
Auth: Bearer
Лимит: 10/IP/мин

Запрос:
    {
      "password": "...",
      "code": "123456"     // обязателен, если 2FA включена
    }

Ответ: 204 (аккаунт удалён)

Ошибки:
    400 — нет pending-записи, отменена, рано или окно истекло
    401 — неверный пароль/код
    409 — окно ещё не открылось / уже закрылось
    429 — залочен

Пример:
    curl -X POST http://host:8080/api/v1/account/delete/confirm \
         -H "Authorization: Bearer $T" \
         -H 'Content-Type: application/json' \
         -d '{"password":"...","code":"123456"}'


--------------------------------------------------------------------------------
POST /api/v1/account/delete/cancel
--------------------------------------------------------------------------------
Auth: Bearer
Ответ: 204
Ошибки: 404 — нет pending-записи


--------------------------------------------------------------------------------
GET /api/v1/account/delete/status
--------------------------------------------------------------------------------
Auth: Bearer

Ответ 200 (есть pending):
    {
      "pending": true,
      "account_id": "<uuid>",
      "initiated_at": 1770000000,
      "confirm_after": 1770000300,
      "confirm_until": 1770000600
    }

Ответ 200 (нет):
    { "pending": false, "account_id": null, "initiated_at": null,
      "confirm_after": null, "confirm_until": null }

4. PROFILE
================================================================================

--------------------------------------------------------------------------------
PUT /api/v1/profile/username
--------------------------------------------------------------------------------
Меняет отображаемое имя.

Auth: Bearer

Запрос:
    { "username": "John Doe" }

Правила:
    1..64 символов, только [A-Za-z0-9_. ] и одиночные пробелы.

Ответ: 204
Ошибки: 400 — недопустимые символы / слишком длинный


--------------------------------------------------------------------------------
PUT /api/v1/profile/status
--------------------------------------------------------------------------------
Устанавливает кастомный статус.

Auth: Bearer

Запрос:
    {
      "text": "работаю",
      "emoji": "💻",
      "ttl_seconds": 3600
    }

Поля:
    text         — до 100 символов, опционально
    emoji        — до 8 символов, опционально
    ttl_seconds  — >0, опционально. Без него — бессрочно.
                   0 или отрицательное — 400.

Ответ: 204
Побочный эффект: presence broadcast всем, кто тебя видит.


--------------------------------------------------------------------------------
DELETE /api/v1/profile/status
--------------------------------------------------------------------------------
Сбрасывает кастомный статус.
Ответ: 204


--------------------------------------------------------------------------------
PUT /api/v1/profile/invisible
--------------------------------------------------------------------------------
Включает/выключает невидимку.

Запрос:
    { "enabled": true }
Ответ: 204


--------------------------------------------------------------------------------
GET /api/v1/profile/presence-exceptions
--------------------------------------------------------------------------------
Список исключений (кому видно/не видно твой presence).

Ответ 200:
    [
      { "target_account_id": "<uuid>", "kind": "always_visible", "created_at": 1770000000 },
      { "target_account_id": "<uuid>", "kind": "always_invisible", "created_at": 1770000100 }
    ]


--------------------------------------------------------------------------------
POST /api/v1/profile/presence-exceptions
--------------------------------------------------------------------------------
Добавляет исключение.

Запрос:
    { "target_account_id": "<uuid>", "kind": "always_visible" }

kind: "always_visible" | "always_invisible"
Ответ: 204
Ошибки: 400 — неверный kind, себя нельзя


--------------------------------------------------------------------------------
POST /api/v1/profile/presence-exceptions/remove
--------------------------------------------------------------------------------
Убирает исключение.

Запрос:
    { "target_account_id": "<uuid>", "kind": "always_visible" }

Ответ: 204
Ошибки: 404 — нет такого


--------------------------------------------------------------------------------

DELETE /api/v1/devices/{device_id}
--------------------------------------------------------------------------------
Отзывает устройство (своё).

Правило: отозвать чужое устройство можно, только если твоё устройство
device_number == 1 ИЛИ старше 3 суток. Иначе 403.

Ответ: 204
Побочный эффект: WS этого девайса получает ErrorFrame { code:"revoked", fatal:true }

8. PREKEYS
================================================================================

--------------------------------------------------------------------------------
POST /api/v1/devices/me/prekeys
--------------------------------------------------------------------------------
Загружает signed prekey, kyber last-resort и one-time prekeys для СВОЕГО
устройства.

Auth: Bearer

Запрос:
    {
      "signed_prekey": {
        "id": 42,
        "pub": "<hex>",
        "sig": "<hex>"
      },
      "kyber_last_resort": {
        "id": 43,
        "pub": "<hex>",
        "sig": "<hex>"
      },
      "one_time_prekeys": [
        { "id": 100, "pub": "<hex>" },
        { "id": 101, "pub": "<hex>" }
      ],
      "kyber_one_time_prekeys": [
        { "id": 200, "pub": "<hex>" }
      ]
    }

Все поля, кроме signed_prekey/kyber_last_resort, опциональны.
Лимит на пул: 200 unconsumed ключей каждого вида на устройство.

Ответ 200:
    {
      "one_time_inserted": 2,
      "kyber_one_time_inserted": 1
    }

Ошибки:
    400 — превышение лимита, невалидный hex
    401 — нет device этого номера


--------------------------------------------------------------------------------
GET /api/v1/devices/me/prekeys/status
--------------------------------------------------------------------------------
Ответ 200:
    {
      "one_time_available": 87,
      "kyber_one_time_available": 42,
      "has_signed_prekey": true,
      "has_kyber_last_resort": true
    }


--------------------------------------------------------------------------------
GET /api/v1/accounts/{account_id}/devices/{device_number}/bundle
--------------------------------------------------------------------------------
Получить bundle для установления сессии с чужим устройством.

Auth: Bearer
Лимит: 10/(account,device)/мин

Каждый вызов расходует одну OTK из пула целевого устройства.

Ответ 200:
    {
      "account_id": "<uuid>",
      "device_number": 1,
      "registration_id": 12345,
      "identity_key_pub": "<hex>",
      "signed_prekey": { "id": 42, "pub": "<hex>", "sig": "<hex>" },
      "kyber_last_resort": { "id": 43, "pub": "<hex>", "sig": "<hex>" },
      "one_time_prekey":       { "id": 100, "pub": "<hex>" } | null,
      "kyber_one_time_prekey": { "id": 200, "pub": "<hex>" } | null
    }

Если OTK-пул у цели <= 3 (MIN_OTK_BEFORE_REPLENISH):
    HTTP 503
    {
      "error": "replenish_required",
      "message": "prekey pool needs replenishing",
      "details": {
        "one_time_available": 2,
        "kyber_one_time_available": 5,
        "minimum_required": 4
      }
    }

Ошибки: 404 — нет такого устройства

11. ATTACHMENTS
================================================================================

Флоу:
  1. POST /attachments/recommend   — узнать оптимальный размер чанка
  2. POST /attachments/init        — получить presigned PUT URL'ы
  3. PUT по каждому URL            — залить чанки напрямую в S3
  4. POST /attachments/{id}/finalize — сервер проверит и сделает "ready"
  5. Отдать attachment_id в сообщении
  6. Получатель: POST /attachments/{id}/claim — взять ссылку на blob


--------------------------------------------------------------------------------
POST /api/v1/attachments/recommend
--------------------------------------------------------------------------------
Auth: Bearer

Запрос:
    { "total_size": 15728640 }

Ответ 200:
    {
      "chunk_size": 3932160,
      "chunk_count": 4,
      "chunk_sizes": [3932160, 3932160, 3932160, 3932160]
    }

Ошибки:
    413 — total_size больше ATTACHMENT_MAX_FILE_SIZE_MB
    400 — слишком много чанков (>500)


--------------------------------------------------------------------------------
POST /api/v1/attachments/init
--------------------------------------------------------------------------------
Auth: Bearer
Лимит: 30/account/мин

Запрос:
    {
      "chunk_sizes": [3932160, 3932160, 3932160, 3932160],
      "conversation_id": "<uuid>",
      "kind": "attachment"          // "attachment" | "thumbnail", дефолт "attachment"
    }

Ограничения:
    - сумма chunk_sizes <= ATTACHMENT_MAX_FILE_SIZE_MB
    - каждый чанк <= 32 MiB (MAX_CHUNK_BYTES)
    - chunk_sizes.len() <= 500
    - ты должен быть участником conversation_id

Ответ 201:
    {
      "attachment_id": "<uuid>",
      "chunk_count": 4,
      "total_size": 15728640,
      "uploads": [
        { "chunk_index": 0, "url": "https://s3.../presigned-put" },
        { "chunk_index": 1, "url": "https://s3.../presigned-put" },
        { "chunk_index": 2, "url": "https://s3.../presigned-put" },
        { "chunk_index": 3, "url": "https://s3.../presigned-put" }
      ]
    }

Ошибки:
    400 — пустые chunk_sizes, неверный kind, чанк слишком большой
    404 — нет такой конверсации или ты не участник
    413 — суммарный размер больше лимита
    429 — rate limit

URL'ы живут 15 минут (PUT_TTL_SECS).


--------------------------------------------------------------------------------
POST /api/v1/attachments/{id}/finalize
--------------------------------------------------------------------------------
После загрузки всех чанков — вызвать, чтобы сервер проверил и пометил как
ready. Сервер делает HEAD каждого объекта, сверяет размер, и (если чанк
<=32 MiB) читает его целиком.

Auth: Bearer

Ответ: 204
Ошибки:
    403 — не твоя аттач
    400 — размер не совпал, чанк отсутствует, чанк слишком большой
    409 — уже finalized


--------------------------------------------------------------------------------
POST /api/v1/attachments/{id}/claim
--------------------------------------------------------------------------------
Получатель (или форвардер) берёт claim на аттач.

Auth: Bearer
Доступ: ты должен быть участником conversation_id аттача (или его
uploader, если conversation_id == NULL для старых аттачей).

Ответ: 204
Ошибки:
    400 — аттач не finalized
    404 — аттач не существует или нет доступа


--------------------------------------------------------------------------------
POST /api/v1/attachments/{id}/release
--------------------------------------------------------------------------------
Освобождает свой claim. Если это был последний claim — удаляет blob из S3
и строку из БД.

Auth: Bearer
Ответ: 204
Ошибки: 404


--------------------------------------------------------------------------------
GET /api/v1/attachments/{id}
--------------------------------------------------------------------------------
Получить presigned GET-URL'ы для скачивания.

Auth: Bearer
Доступ: участник конверсации или uploader (для legacy с NULL conversation).

Ответ 200:
    {
      "attachment_id": "<uuid>",
      "total_size": 15728640,
      "chunk_count": 4,
      "chunks": [
        { "chunk_index": 0, "size_bytes": 3932160, "url": "https://s3..." },
        { "chunk_index": 1, "size_bytes": 3932160, "url": "https://s3..." },
        { "chunk_index": 2, "size_bytes": 3932160, "url": "https://s3..." },
        { "chunk_index": 3, "size_bytes": 3932160, "url": "https://s3..." }
      ]
    }

Ошибки:
    400 — аттач не finalized
    404 — нет или нет доступа

URL'ы живут 15 минут (GET_TTL_SECS).

--------------------------------------------------------------------------------

Как это работает при получении:
    Сервер отправляет POST на url с заголовком
        X-Bot-Secret: <secret_token>
    и телом:
        {
          "updates": [
            {
              "update_id": 12345,
              "type": "message",
              "data": { … }
            }
          ]
        }
    Успех = 2xx. Иначе — retry на следующем тике (раз в 2 секунды).

При удалении webhook все pending-обновления дропаются.

23. WEBSOCKET
================================================================================
URL: ws://host:8080/ws

Лимиты:
    max message size:  256 KiB
    max frame size:    256 KiB
    max write buffer:  256 KiB
    hello timeout:     10 секунд
    флуд:              100 фреймов/сек в течение 5 секунд подряд = disconnect

Формат: бинарные protobuf-фреймы (prost).
Первый фрейм клиента — ОБЯЗАТЕЛЬНО ClientFrame::Hello.


Хендшейк
--------------------------------------------------------------------------------
1. Клиент → сервер:

    ClientFrame {
      kind: Hello {
        session_token: "<из /login>",
        device_number: <n>,          // должен совпадать с device_number сессии
        client_name: "friendshub-web 1.0"
      }
    }

2. Сервер → клиент (или Error + close):

    ServerFrame {
      kind: Hello {
        session_id: "<uuid>",
        account_id: <16 bytes>,
        device_number: <n>,
        server_timestamp: <unix>,
        protocol_major: 0, protocol_minor: 1, protocol_patch: 0
      }
    }

3. Сервер может сразу отдать backlog неотданных конвертов:

    ServerFrame {
      kind: Delivery {
        envelopes: [
          { envelope_id, sender_account_id, sender_device_number,
            recipient_account_id, recipient_device_number,
            envelope_type, is_prekey_message, ciphertext,
            client_timestamp, conversation_id, sender_is_bot }
        ]
      }
    }

Дальше — обычный поток фреймов.


Client → Server
--------------------------------------------------------------------------------
ClientFrame::Hello      — только один раз, в самом начале
ClientFrame::Ping       — { client_timestamp }
ClientFrame::Upload     — { envelopes: [Envelope] }   // до 128 конвертов
ClientFrame::Ack        — { envelope_ids: [16 bytes] } // подтверждение доставки


Server → Client
--------------------------------------------------------------------------------
ServerFrame::Hello      — после handshake
ServerFrame::Pong       — { client_timestamp, server_timestamp }
ServerFrame::Receipt    — { envelope_ids: [...] } — сервер принял и сохранил
ServerFrame::Delivery   — { envelopes: [...] } — пришли новые конверты
ServerFrame::Presence   — { account_id, is_online, last_seen, custom_status_* }
ServerFrame::ChannelPost — { post_id, channel_id, author_type, author_id,
                            text, attachment_ids, reply_to_post_id, created_at }
ServerFrame::BotMessage — { message_id, bot_id, account_id, text,
                            reply_to_message_id, created_at }
ServerFrame::Error      — { code, message, fatal }


Отправка сообщений (EnvelopeUpload)
--------------------------------------------------------------------------------
Клиент → сервер:

    ClientFrame {
      kind: Upload {
        envelopes: [
          {
            envelope_id:              <16 bytes>,
            sender_account_id:        <16 bytes>,   // твой account_id
            sender_device_number:     <n>,
            recipient_account_id:     <16 bytes>,
            recipient_device_number:  <n>,
            envelope_type:            <1..17>,
            is_prekey_message:        true | false,
            ciphertext:               <bytes, <= 64 KiB>,
            client_timestamp:         <unix>,
            conversation_id:          <16 bytes>    // пусто = "не в чате"
          }
        ]
      }
    }

Ограничения сервера:
    до 128 конвертов в одном Upload
    ciphertext <= 64 KiB
    envelope_type в диапазоне 1..=17
    sender_account_id должен совпадать с твоим account_id
    recipient_device должен существовать и не быть revoked
    recipients с блокировкой в любую сторону — дропаются молча

Сервер → клиент (подтверждение):
    ServerFrame::Receipt {
      envelope_ids: [<16 bytes>, ...]     // те, что реально сохранились
    }

Важно: envelope с уже существующим id игнорируется (ON CONFLICT DO NOTHING).
Повторная отправка того же envelope_id не создаёт дубликат и не рассылает
live повторно.


Получение сообщений
--------------------------------------------------------------------------------
1. Онлайн получатель:
    ServerFrame::Delivery { envelopes: [...] }  летит сразу на device.

2. Офлайн — сервер копит в БД, отдаёт при подключении через backlog
   (ServerFrame::Delivery в handshake) или до тех пор пока клиент не отправит
   ServerFrame::Ack с этим id.

3. Подтверждение получения (клиент):
    ClientFrame {
      kind: Ack {
        envelope_ids: [<16 bytes>, ...]
      }
    }

После ack сервер помечает envelope как acked и больше не отдаёт его в
backlog. Envelope'ы в saved-конверсациях не удаляются TTL даже после ack.


Отправка в saved
--------------------------------------------------------------------------------
См. раздел 10. Отличается только тем, что:
  - recipient_account_id = твой
  - conversation_id      = id из GET /saved
  - нужно N конвертов — по одному на каждое СВОЁ активное устройство,
    кроме текущего


Ping/Pong
--------------------------------------------------------------------------------
Клиент отправляет Ping, сервер отвечает Pong:

    ClientFrame  { kind: Ping { client_timestamp } }
    ServerFrame  { kind: Pong { client_timestamp, server_timestamp } }

Флуд-контроль: 100 фреймов/сек. Пять секунд подряд выше — disconnect.


Ошибки
--------------------------------------------------------------------------------
ServerFrame::Error {
  code:    "protocol" | "unauthorized" | "device_mismatch" | "flood" | …
  message: "…",
  fatal:   true | false
}

fatal=true  — сервер закрывает соединение.
Коды fatal:
    handshake        — не получили Hello за 10 сек
    timeout          — то же
    protocol         — несовпадение major
    unauthorized     — нет/протух токен
    device_mismatch  — Hello.device_number != session.device_number
    session_revoked  — сессия отозвана
    device_revoked   — девайс отозван
    replaced         — этот девайс подключился заново
    flood            — флуд фреймами
    account_deleted  — аккаунт удалён


Переподключение
--------------------------------------------------------------------------------
1. Backoff: 1s, 2s, 4s, 8s, … max 30s.
2. При подключении — Hello с тем же session_token.
3. Если получил fatal (кроме flood) — не переподключаться, идти в /login.
