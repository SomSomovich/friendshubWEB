# Crypto module (wasm-pack output)

This directory holds the WebAssembly crypto engine: all Signal Protocol work
(sessions, prekeys, sender keys, attachment sealing) happens inside it. Nothing
in `src/` implements any of it in JavaScript, and nothing here should be edited
by hand — the whole directory is generated.

Source of truth: <https://github.com/SomSomovich/friendshub-wasm>
(AGPL-3.0-only, built against libsignal-protocol v0.103.1).

## What is committed and what is not

| File | In git | Why |
| --- | --- | --- |
| `friendshub_wasm.js` | yes | the JS glue generated by wasm-pack |
| `friendshub_wasm.d.ts`, `friendshub_wasm_bg.wasm.d.ts` | yes | type surface for the glue |
| `package.json` | yes | marks the directory as an ES module package |
| `friendshub_wasm_bg.wasm` | **no** | a ~1.3 MiB binary build artifact |

`friendshub_wasm_bg.wasm` is excluded by the `.gitignore` in this directory.
`npm run fetch-wasm` (wired as a `predev`/`prebuild` hook) copies it in from a
sibling checkout of `friendshub-wasm`.

## Getting the binary

```bash
npm run fetch-wasm
```

Resolution order:

1. `$FRIENDSHUB_WASM_PKG` — a directory containing `friendshub_wasm_bg.wasm`
2. `../friendshub-wasm/pkg` — the source repository cloned next to this project

The script is idempotent: it compares SHA-256 and only copies when the file is
missing or stale. To fetch from somewhere else:

```bash
FRIENDSHUB_WASM_PKG=/path/to/friendshub-wasm/pkg npm run fetch-wasm
```

## Rebuilding from source

```bash
git clone https://github.com/SomSomovich/friendshub-wasm
cd friendshub-wasm
wasm-pack build --target web      # writes pkg/, including the .wasm
```

Then copy `pkg/friendshub_wasm_bg.wasm` into this directory — but keep the
`.js` and `.d.ts` files in sync too: a rebuilt module usually changes the
generated glue, and `scripts/fetch-wasm.mjs` deliberately moves only the binary.
For a rebuild that changes the API surface, copy the whole `pkg/` directory
(except `.gitignore`) and commit the glue alongside the type-only changes.

## Tests

`npm run smoke:wasm` exercises the whole module through `src/wasm/index.ts` in
Node — instantiation, identity, prekeys, snapshot/restore, attachment chunks and
the sender-key path — and prints any place where the module disagrees with
`WASM_API.txt`.
