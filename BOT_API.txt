================================================================================
FRIENDSHUB — BOT API
Версия: 1.0
Base URL: https://<host>/api/bot/v1
================================================================================

--------------------------------------------------------------------------------
1. ОБЩИЕ СВЕДЕНИЯ
--------------------------------------------------------------------------------

1.1. Назначение
    Bot API позволяет владельцу бота писать автоматизированных клиентов,
    которые получают апдейты от пользователей (через long polling или
    webhook) и могут отправлять сообщения, а также публиковать посты в
    каналах, где боту выдана роль admin или owner.

1.2. Аутентификация
    Каждый запрос Bot API, кроме /health, обязан содержать заголовок:

        X-Bot-Token: fhbot_<...>

    Токен выдаётся ровно один раз при создании бота (POST /api/v1/bots)
    либо при ротации (POST /api/v1/bots/{id}/rotate-token). Хранится в
    виде хеша; при утечке его можно отозвать ротацией.

1.3. Формат ошибок
    Идентичен клиентскому API:

        {
          "error": "not_found|unauthorized|forbidden|bad_request|conflict|
                    rate_limited|payload_too_large|internal_error",
          "message": "...",
          "details": { ... }         // опционально
        }

1.4. Rate limit
    Лимиты привязаны к bot_id:

        GET /accounts/{fh_number}   — 60/мин (BOT_LOOKUPS_PER_MINUTE)
        GET /getUpdates             — 60/мин (GET_UPDATES_PER_MINUTE)

    Ответ с 429 содержит Retry-After (в секундах).

1.5. Соглашение об идентификаторах
    - id аккаунтов, ботов, каналов — UUID-строки
    - update_id — возрастающее целое число (bigserial)
    - created_at, started_at и т.п. — unix-время в секундах (int64)

--------------------------------------------------------------------------------
2. GET /me — информация о текущем боте
--------------------------------------------------------------------------------

    Запрос:
        GET /api/bot/v1/me
        X-Bot-Token: fhbot_...

    Ответ 200:
        {
          "bot_id": "...",
          "owner_account_id": "...",
          "token_prefix": "fhbot_0123456789",
          "handle": "mybot",         // null, если handle не установлен
          "created_at": 1799999000
        }

    Ошибки:
        401 unauthorized — токен отсутствует или неверен

--------------------------------------------------------------------------------
3. GET /health — проверка живости
--------------------------------------------------------------------------------

    Ответ 200: { "ok": true }

    Не требует токена.

--------------------------------------------------------------------------------
4. GET /accounts/{fh_number} — поиск пользователя по FH-номеру
--------------------------------------------------------------------------------

    Запрос:
        GET /api/bot/v1/accounts/FH1234567
        X-Bot-Token: fhbot_...

    Ответ 200:
        {
          "account_id": "...",
          "user_id": 42,
          "fh_number": "FH1234567",
          "username": "Alice",
          "avatar_url": null
        }

    Ошибки:
        404 not_found — аккаунт не найден
        429 rate_limited — 60/мин на бота

    Замечание: пространство FH-номеров перечислимо. Лимит здесь есть,
    чтобы один бот не мог обойти весь диапазон.

--------------------------------------------------------------------------------
5. GET /getUpdates — long polling апдейтов
--------------------------------------------------------------------------------

5.1. Запрос

        GET /api/bot/v1/getUpdates?offset=0&limit=100&timeout=30
        X-Bot-Token: fhbot_...

    Параметры (query):
        offset   — int64; возвращаются апдейты с id > offset. По умолчанию 0.
                   Отрицательные значения приводятся к 0.
        limit    — int64; 1..500, по умолчанию 100.
        timeout  — секунды long polling. 0 = вернуть сразу.
                   Максимум 60. Если апдейтов нет, сервер держит запрос
                   до `timeout` секунд, опрашивая БД раз в 5 секунд.

5.2. Ответ 200

        {
          "updates": [
            {
              "update_id": 12345,
              "update_type": "message",
              "data": {
                "message_id": "...",
                "bot_id": "...",
                "account_id": "...",     // id отправителя
                "text": "привет",
                "reply_to_message_id": null,
                "created_at": 1799999000
              },
              "created_at": 1799999000
            }
          ]
        }

    Если апдейтов нет — { "updates": [] }.

    Поле `data` — это тот же JSON, который бот получил бы в webhook
    (см. раздел 7).

5.3. Семантика update_id

    update_id монотонно растёт. Бот должен хранить последний обработанный
    update_id и передавать его как offset в следующий запрос:

        offset = last_update_id + 1

    Сервер вернёт все апдейты с id > offset.

5.4. Ограничения

    - не более 10000 неотданных апдейтов на бота (MAX_PENDING_PER_BOT)
    - если очередь заполнена, POST /api/bot/v1/sendMessage от лица
      пользователя вернёт 409 conflict
    - неотданные апдейты старше 30 дней удаляются автоматически
    - отданные апдейты старше 7 дней удаляются автоматически

5.5. Ошибки

        429 rate_limited — 60/мин на бота

    Если у бота установлен webhook, вызов getUpdates допускается, но
    сервер доставляет только «застрявшие» апдейты. Обычно боты используют
    что-то одно.

--------------------------------------------------------------------------------
6. WEBHOOK: setWebhook / deleteWebhook / getWebhook
--------------------------------------------------------------------------------

6.1. POST /setWebhook

    Запрос:
        POST /api/bot/v1/setWebhook
        X-Bot-Token: fhbot_...

        {
          "url": "https://example.com/mybot/hook",
          "secret_token": "a-very-long-secret-string-16-256"
        }

    Ограничения:
        url — https, порт 443, публичный (не loopback, не 10/8, не
              172.16/12, не 192.168/16, не 169.254/16, не 100.64/10,
              не IPv6 ULA/link-local/loopback, не NAT64/6to4/Teredo),
              длина ≤ 2048
        secret_token — 16..256 символов; если не передан, сервер
                       сгенерирует сам

    Ответ 204.

    Ошибки:
        400 bad_request — URL не подходит (не https/443/публичный)

6.2. POST /deleteWebhook

    Ответ 204. Все неотданные апдейты бота при этом удаляются —
    доставлять их больше некуда.

6.3. GET /getWebhook

    Ответ 200, если webhook установлен:
        {
          "url": "https://example.com/mybot/hook",
          "active": true,
          "created_at": 1799999000,
          "updated_at": 1799999000
        }

    Если webhook не установлен:
        {
          "url": null,
          "active": false,
          "created_at": null,
          "updated_at": null
        }

6.4. Формат доставки

    Сервер делает POST на url с заголовком:

        X-Bot-Secret: <secret_token>

    Тело — JSON:

        {
          "updates": [
            {
              "update_id": 12345,
              "type": "message",
              "data": {
                "message_id": "...",
                "bot_id": "...",
                "account_id": "...",
                "text": "привет",
                "reply_to_message_id": null,
                "created_at": 1799999000
              }
            }
          ]
        }

    Успехом считается ответ 2xx. На не-2xx или таймаут до 10 секунд
    апдейт остаётся неотданным и будет переотправлен на следующем тике
    (интервал 2 секунды, до 50 апдейтов за раз).

    DNS резолвится один раз на момент доставки, соединение пиннится к
    проверенным адресам. Редиректы не следуются.

6.5. Прекращение доставки

    Если URL перестал быть публичным (например, DNS сменился на
    внутренний адрес), сервер молча пропускает доставку и пишет warning
    в лог. Рекомендуется периодически вызывать getWebhook и, при
    необходимости, переставлять URL.

--------------------------------------------------------------------------------
7. POST /sendMessage — сообщение пользователю
--------------------------------------------------------------------------------

    Запрос:
        POST /api/bot/v1/sendMessage
        X-Bot-Token: fhbot_...

        {
          "account_id": "UUID получателя",
          "text": "текст сообщения",
          "reply_to_message_id": null
        }

    Ограничения:
        text — 1..4096 символов
        получатель должен хотя бы раз написать боту (см. ниже)

    Ответ 201:
        {
          "message_id": "...",
          "created_at": 1799999000
        }

    Доставка: если пользователь онлайн, сообщение уходит по WebSocket
    во все его устройства (кадр BotMessage). Оффлайн — ничего не теряется,
    история хранится в bot_messages и доступна через
    GET /api/v1/bots/{id}/messages.

    Правило «первым пишет пользователь»:
        Бот может отправить сообщение ТОЛЬКО тому аккаунту, который
        уже писал этому боту. Это защищает пользователей от спама и
        от того, чтобы бот по одному лишь account_id мог достучаться
        до любого.

    Ошибки:
        400 bad_request  — пустой текст или > 4096
        403 forbidden    — пользователь никогда не писал этому боту
        404 not_found    — account_id не существует
        409 conflict     — очередь апдейтов бота переполнена

--------------------------------------------------------------------------------
8. POST /channels/publish — публикация в канал
--------------------------------------------------------------------------------

    Запрос:
        POST /api/bot/v1/channels/publish
        X-Bot-Token: fhbot_...

        {
          "channel_id": "...",
          "text": "Новый пост",
          "attachment_ids": [],
          "reply_to_post_id": null
        }

    Требования:
        - бот должен быть участником канала с ролью owner или admin
        - text — 1..4096 символов
        - attachment_ids — не более max_files_per_message
        - каждый attachment_id должен быть финализированным вложением
          именно этого канала
        - reply_to_post_id, если задан, должен существовать и принадлежать
          тому же каналу

    Ответ 201:
        {
          "post_id": "...",
          "created_at": 1799999000
        }

    После сохранения пост рассылается по WebSocket всем подписчикам
    канала (кадр ChannelPost) с author_type = "bot".

    Ошибки:
        400 bad_request — невалидный reply_to_post_id, невалидные
                          attachment_ids, пустой текст
        403 forbidden   — бот не admin/owner канала
        404 not_found   — канал не существует

--------------------------------------------------------------------------------
9. ТИПОВЫЕ СЦЕНАРИИ
--------------------------------------------------------------------------------

9.1. Эхо-бот через long polling

    Шаг 1. Создать бота:
        POST /api/v1/bots         (с Authorization: Bearer <user token>)
        → { "bot_id": "...", "token": "fhbot_..." }

    Шаг 2. Установить handle (опционально):
        POST /api/v1/bots/{bot_id}/profile
        { "handle": "echobot" }

    Шаг 3. Опрос:
        GET /api/bot/v1/getUpdates?offset=<last+1>&timeout=30
        X-Bot-Token: fhbot_...

    Шаг 4. Обработать updates и при необходимости ответить:
        POST /api/bot/v1/sendMessage
        X-Bot-Token: fhbot_...
        {
          "account_id": "<из update.data.account_id>",
          "text": "<эхо>"
        }

9.2. Эхо-бот через webhook

    Шаг 1–2. Как выше.

    Шаг 3. Установить webhook:
        POST /api/bot/v1/setWebhook
        {
          "url": "https://my.bot/hook",
          "secret_token": "my-very-secret-token-here"
        }

    Шаг 4. Принимать POST на /hook, проверять заголовок X-Bot-Secret,
    разбирать { "updates": [...] } и реагировать через sendMessage.

9.3. Публикация в канал от имени бота

    Шаг 1. Владелец бота должен добавить бота в канал:
        POST /api/v1/channels/{channel_id}/bots
        { "bot_id": "..." }

    Шаг 2. Владелец канала (не бот!) назначает боту роль admin:
        POST /api/v1/channels/{channel_id}/members/role
        { "actor_type": "bot", "actor_id": "<bot_id>", "role": "admin" }

    Шаг 3. Публикация:
        POST /api/bot/v1/channels/publish
        {
          "channel_id": "...",
          "text": "Обновление сервиса"
        }

--------------------------------------------------------------------------------
10. БЕЗОПАСНОСТЬ
--------------------------------------------------------------------------------

10.1. Хранение токена
     Токен показывается один раз при создании и при ротации. Сервер
     хранит только SHA-256 от токена. При подозрении на утечку —
     POST /api/v1/bots/{id}/rotate-token (со стороны владельца).

10.2. Webhook secret
     Секрет передаётся в заголовке X-Bot-Secret каждого POST.
     Проверяйте его перед обработкой. Если секрет не задан при
     setWebhook, сервер сгенерирует его сам.

10.3. SSRF
     Сервер не пойдёт по адресу, который не является публичным
     https-эндпоинтом на порту 443. Редиректы не следуются.
     DNS резолвится один раз на момент доставки и «прибивается» —
     между проверкой и запросом адрес не может измениться.

10.4. Лимиты
     Бот — это тоже клиент. Все, что ограничено по account_id в
     клиентском API, ограничено по bot_id здесь. Если у вас много ботов,
     каждый из них имеет свои бакеты лимитов, но количество ботов на
     аккаунт ограничено 20.
